> AI-powered analytics dashboard for microinverter fleet, RMA, and telemetry data — fully client-side, zero data leaves the browser.

CompDash GPT combines in-browser SQL (DuckDB-WASM) with a locally-hosted LLM (Ollama) to deliver natural-language analytics over proprietary fleet and telemetry data — without ever sending that data to any cloud service.

---

## Zero-Data Architecture

**No proprietary data is stored in this repository.**

| Data type | Where it lives | How it gets in |
|-----------|---------------|----------------|
| Fleet parquet | Your machine only | `public/fleet-data/` (gitignored) |
| RMA parquet | Your machine only | `public/fleet-data/` (gitignored) |
| Telemetry CSV | Your machine only | Uploaded via Upload page (in-session) |
| LLM inference | Your local Ollama instance | Configured at runtime in-browser |

Deployed users load their own parquet files through the **Data Sources** upload page (`/data`). Files are parsed entirely in the browser via DuckDB-WASM and never transmitted anywhere.

## Features

### Ask a Question (AI-Powered NL Query)
- Natural-language questions routed to the right analytical tool automatically
- Intents: site analysis, microinverter analysis, energy totals, time series, anomaly detection, clipping, peer comparison, fleet search, nearby sites
- **Site Analysis Agent** — 10-step workflow: fleet profile → peer discovery → telemetry → energy trends → per-inverter stats → anomaly detection → clipping → RMA → peer benchmarking
- **Microinverter Analysis Agent** — telemetry-only: AC power stats, voltage/frequency/temperature, clipping detection, daily production
- Conversation context preserved across turns for follow-up questions
- LLM endpoint and model configurable at runtime (no rebuild needed)

### Fleet Analytics
| Page | Description |
|------|-------------|
| **Fleet Overview** | KPI cards, wafer/product distribution, geographic heatmap |
| **Wafer Detail** | Wafer-level breakdown with module compatibility checks |
| **Product Buckets** | Power bucket distribution across product types |
| **Fleet Transition** | Quarter-over-quarter trends in power, DC/AC ratio, wafer mix |
| **Fleet Compliance** | Cat 1 (208 L-L), Cat 2 (Three-Phase), Cat 3 (Module Compatibility) violation detection with RMA correlation |

### Telemetry Analytics
| Page | Description |
|------|-------------|
| **Overview** | Site-level KPIs with 7-day sparklines |
| **Site Comparison** | Multi-site line charts, overlay/split view |
| **Inverter Drilldown** | Z-score anomaly badges, threshold analysis, cross-site comparison |
| **Anomaly Detection** | Z-score slider, heatmap, distribution chart |
| **Clipping Analysis** | Power and current clipping detection with flat-run algorithm |
| **Bucket Analysis** | Power/voltage/frequency distribution histograms |
| **Developer** | Multi-axis chart builder, per-metric statistics |

### Data Loading
- **Local dev**: place `fleet_data.parquet` + `rma_data.parquet` in `public/fleet-data/` — auto-loaded on startup
- **Deployed**: drag-and-drop upload via `/data` page — files stay in browser memory (DuckDB-WASM), never uploaded
- **Telemetry**: CSV upload via `/upload` page, session-persisted

## Local Development

### Prerequisites
- Node.js 20+
- Python 3.11+ (for data preparation scripts only)
- [Ollama](https://ollama.ai) running locally with `qwen3:14b` (for Ask a Question)

### Setup

```bash
git clone https://github.com/Akhlad123/CompDash-GPT.git
cd CompDash-GPT
npm install
npm run dev
```

Open [http://localhost:5173](http://localhost:5173)

### Data files (local only — never commit)

Place your parquet files in `public/fleet-data/` — they are gitignored:

```
public/fleet-data/fleet_data.parquet   ← generated by scripts/prepare_fleet_data.py
public/fleet-data/rma_data.parquet     ← generated by scripts/prepare_rma_data.py
```

### Generating parquet files

```bash
# Fleet data (from Excel source files)
py scripts/prepare_fleet_data.py

# RMA data (from CSV export)
py scripts/prepare_rma_data.py --input path/to/rma_export.csv
```

See `public/fleet-data/README.md` for full instructions on adding new quarters.

### Ollama setup

```bash
# Install Ollama from https://ollama.ai, then:
ollama pull qwen3:14b
ollama serve
```

The app defaults to `http://localhost:11434`. Change the URL and model at runtime via the ⚙️ settings icon on the Ask a Question page — persisted in browser `localStorage`.

## Deployment (Cloudflare Pages)

### Build

```bash
npm run build
# Output: dist/
```

### Cloudflare Pages settings

| Setting | Value |
|---------|-------|
| Build command | `npm run build` |
| Output directory | `dist` |
| Environment variables | None required |

The `public/_headers` file automatically sets COOP/COEP headers required for DuckDB-WASM multi-threading:

```
/*
  Cross-Origin-Embedder-Policy: require-corp
  Cross-Origin-Opener-Policy: same-origin
```

### Ollama on Oracle Cloud (or any VM)

For deployed users to use Ask a Question, run Ollama on a VM accessible over HTTPS:

```bash
# On the VM
OLLAMA_ORIGINS="*" ollama serve

# Pull the model
ollama pull qwen3:14b
```

Users configure the Ollama base URL (e.g. `https://your-vm-ip:11434`) via the ⚙️ settings icon on the Ask a Question page.

## Gitignore Policy

The following are **always excluded** from the repository:

```
public/fleet-data/*.parquet   # Fleet data
public/fleet-data/*.xlsx      # Source Excel files
public/fleet-data/*.csv       # CSV exports
dist/fleet-data/*             # Built artifacts
public/sample/*.csv           # Telemetry samples (except committed demo file)
.env / .env.*                 # Secrets
```

If you accidentally stage a data file, run:
```bash
git rm --cached public/fleet-data/fleet_data.parquet
git rm --cached public/fleet-data/rma_data.parquet
```
