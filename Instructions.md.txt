# CompDash GPT — Fleet + Telemetry Analytics with NL Query

A fork of CompDash that adds a Fleet Analytics module (wafer/power-bucket
breakdowns by region, country, and quarter, precomputed irradiance) and a
natural-language query tool, alongside the existing telemetry comparison
features. Fleet and Telemetry data are cross-linked by Site ID. The Ask a
Question route is now being migrated, without changing other pages, into an
Azure-managed AI analytics workspace for fleet, telemetry, weather, solar
engineering, and approved technical documents.

> **⚠️ Confidential data — private hosting only.** The bundled Fleet dataset is
> proprietary company data. Do NOT push it to a public repository, deploy it to
> GitHub Pages/Netlify, or share `public/fleet-data/` externally. Until approved
> private Azure hosting exists, run the bundled dataset locally (`npm run dev` /
> `npm run preview`). The future Ask API and telemetry platform deploy only to
> approved private Azure resources; never expose fleet data or API credentials publicly.

## Refreshing Fleet Data (new quarter)

The bundled dataset is `public/fleet-data/fleet_data.parquet`, generated by
`scripts/prepare_fleet_data.py` from the master Excel/CSV export. Parquet
(zstd-compressed) is used instead of CSV because this dataset accumulates
2-3 years of cumulative quarterly history — the raw source file can grow to
~950 MB, but Parquet compresses it ~6x smaller (measured: 32.1 MB CSV vs
5.4 MB Parquet for the same 157,788 rows), keeping the bundled asset safe to
load into browser memory.

1. Get the latest cumulative export (Excel `.xlsx` or CSV — both supported)
   containing all quarters to date, not just the newest one.
2. If new geographies are introduced, re-run the irradiance precompute:
   ```bash
   py "Fleet data analytics/irradiance/fetch_irradiance.py"
   ```
3. Regenerate the bundled Parquet file:
   ```bash
   cd scripts
   py prepare_fleet_data.py --input "C:/path/to/latest_export.xlsx"
   ```
   (Omit `--input` to use the default path configured in the script.)
4. Restart `npm run dev` / rebuild to pick up the refreshed Parquet file.

## Ask a Question Platform

The production implementation is isolated to the Ask a Question route. It adds:

- A React feature module under `src/features/ask-question/`, composed only by
  `src/pages/QueryPage.tsx`.
- A FastAPI API for authenticated conversations, analysis runs, SSE streaming,
  governed query planning, result artifacts, and audit records.
- Microsoft Entra ID authentication, Azure Key Vault secrets, and managed-identity
  service access.
- PostgreSQL + pgvector for app state, semantic metric catalog, governance, and
  technical-document retrieval; Redis for cache and async work coordination.
- Azure Data Explorer and ADLS Gen2 for 100M+ telemetry records and rollups.
- LangGraph for typed orchestration, Polars for bounded analysis jobs, Plotly for
  Ask-page charts, and AG Grid for server-side paginated result tables.

The browser never calls AI/data services directly, executes generated SQL/KQL, or
receives unbounded telemetry rows. Answers must display scope, time range, source
freshness, confidence, assumptions, caveats, and document citations when relevant.

See `C:\Users\makhlad\.windsurf\plans\compdash-ask-question-ai-platform-2fc71c.md`
for the ordered implementation milestones and acceptance criteria.

## Legacy NL Query — LLM Fallback Setup (optional)

The NL query tool works fully offline via a rule-based parser
(`src/lib/nlQueryParser.ts`). It only calls the LLM when that parser returns
'low' confidence. To test the LLM fallback for ambiguous questions **locally**
(no deployment needed):

1. `netlify-cli` is already installed as a devDependency (see `package.json`).
2. Copy `netlify-env.example.txt` values into a local `.env` file (gitignored,
   never committed) and fill in your real `OPENAI_API_KEY`.
3. Run `npm run netlify-dev` instead of `npm run dev` — this serves the app
   AND runs `netlify/functions/nl-query-fallback.ts` locally at the same time
   (default: http://localhost:8888).
4. In the Query page, ask a question specific enough to trigger low
   confidence (e.g. something with no matching region/metric keywords) to see
   the "LLM fallback" badge appear next to the result.

In production (once a private-hosting solution is approved), set
`OPENAI_API_KEY` as a Netlify environment variable — never commit it or
expose it in client code (see `CompDashGPT.windsurfrules.txt` rule 12).

## Deployment

### Current local mode

The existing static app and bundled Fleet Parquet remain local-only until private
hosting is approved. Use `npm run dev` or `npm run preview`; do not publish
proprietary data or Netlify fallback configuration.

### Ask a Question production target

Deploy only to approved private Azure resources:

- Azure Front Door + WAF
- Azure Container Apps for FastAPI API, workers, and jobs
- Azure Container Registry
- Azure Database for PostgreSQL Flexible Server + pgvector
- Azure Cache for Redis
- Azure Data Explorer and Azure Data Lake Storage Gen2
- Azure Key Vault, Application Insights, Log Analytics, and Microsoft Entra ID

Provision resources using Bicep or Terraform through remote CI/CD. Production
secrets stay in Key Vault, workloads use managed identities, and backend/data
services use private networking where approved. No company laptop should need a
local database, Redis server, Docker Desktop, or Kubernetes installation.
